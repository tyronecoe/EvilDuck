# H1 prototype contract — experimental EvilDuck policy

This is an explicitly selected experiment, **not canonical Hak5 INJECT_VAR compatibility**. Existing profiles/files/artifacts are unchanged. New disposable sources require `EVILDUCK_EXPERIMENTAL_INJECT_VAR_H1=1`; absence/zero fails the new candidate build rather than silently enabling the experiment. Accepted/default builders never apply this delta and keep their original rejection. Build ID: **ROUTEB-INJECT-VAR-H1-EXPERIMENTAL-v1**.

## Grammar and values

```ducky
VAR $KEY = $_RANDOM_LOWER_LETTER_KEYCODE
VAR $COPY = $KEY
INJECT_VAR $COPY
INJECT_VAR $COPY
```

Exact command operand: one raw ordinary `$identifier`, subject to existing identifier bounds/declaration/initialization rules. No numeric literal, expression, direct internal getter, DEFINE-generated operand alias, bare command or additional argument. Inline REPEAT's existing leaf allowlist stays unchanged, so INJECT_VAR is not admitted there; separate statements, existing loops and functions support repetition. Malformed retained source rejects before output even in inactive runtime branches/unused functions; preprocessing exclusions retain their separate treatment.

Six read-only internal operands are appended at IDs11–16: `$_RANDOM_LOWER_LETTER_KEYCODE`, `$_RANDOM_UPPER_LETTER_KEYCODE`, `$_RANDOM_LETTER_KEYCODE`, `$_RANDOM_NUMBER_KEYCODE`, `$_RANDOM_SPECIAL_KEYCODE`, `$_RANDOM_CHAR_KEYCODE`. They use existing bounded unbiased sampling and alphabets: a–z; A–Z; lowercase then uppercase;0–9; `!@#$%^&*()`; their72-character combined alphabet. The inherited RANDOM_CHAR spacing interpretation is project policy, not newly established official behavior. No writable seeds/ranges/keycode controls are added.

Each getter reference selects once through existing expression continuations; assignment captures one scalar, copying copies it and injection does not mutate it. H1 defines that scalar as `(modifier_mask << 8) | HID_usage`. Literal assignments can represent valid pairs in this experiment; ordinary numeric variables have no provenance tag. Consequently a RANDOM_INT-derived scalar can accidentally equal a valid pair, but it is not decimal printing, a guaranteed keycode producer or evidence of Hak5's numeric contract. The command's direct getter operand form is intentionally rejected.

## Decoder and delivery

`decodeExperimentalKeycodeH1` accepts only exact usage/modifier pairs generated by the existing US translator for95printable ASCII characters32–126. Modifiers are zero or leftShift0x02. Unsupported bits, modifier-only, reserved/nonprintable usages,0 and65535 reject before that operation submits a report. Shift+Space is not accepted because it is not a canonical pair in that US printable map. AltGr, dead keys, non-US mapping, arbitrary16bit values and special/modifier keys are outside the experiment. These validity choices are EvilDuck policy, not observed Hak5 errors.

Runtime resolves the variable once, validates/decodes it, then caches a normal `KeyTap` event. Existing jitter, dwell, ownership, held/transient merge, collision/rollover refusal, result matching and restoration are reused. Held Shift can uppercase an otherwise unshifted key just as on the ordinary path; no host Caps normalization or stronger key-release guarantee is added. Retry does not resample/re-evaluate; ambiguous acceptance never replays. STOP/error/disconnect cleanup and quarantine remain the existing implementation. New Op and ErrorCode are appended, with all prior enum values preserved. No adapter/backend/descriptor/USB/storage/settings/EDR1 change occurs.

The three generated changes are core.cpp/core.h/caps_trial.h; [source manifest](../tests/inject_var_experimental/source-manifest.json) pins parent, patch and before/after hashes. [Preparation](../tests/inject_var_experimental/prepare_sources.py) modifies disposable copies only. No second interpreter, heap buffer, copied Program/source or new per-key state lifetime is needed. Current-source software behavior, selected official compiler evidence and physical observations have separate receipts/statuses.

[Reference evidence](inject-var-experimental-evidence.md) explains why H1 is plausible but unproven. [Prepared genuine reference kit](inject-var-experimental-reference-trial.md) can distinguish competing predictions when a separately authorized correlated runtime observation exists. A passing self-authored codec test does not settle that question.
