# Stage 13 source compatibility design (recorded before production changes)

Baseline: Stage12 f3841747fee7ff79c381723d1e578e5d65410011. No hardware, language interpreters, downloads, file inclusion, USB descriptor changes or Stage14 work.

Reference: provenance-verified Stage9 official Hak5 Markdown snapshots for comments, keystroke injection, extensions, conditional compilation and LED. Fresh conditional-compilation Markdown and its alias example image returned HTTP403 on this investigation. The Hak5-owned usbrubberducky-payloads repository at 4fa639fd06972cd7efd9c48cc73136443f9cffb1 independently shows STRING_BASH/STRING_POWERSHELL ending END_STRING, and STRINGLN_BASH/STRINGLN_POWERSHELL ending END_STRINGLN. Community payloads are supporting examples, not an independent compiler oracle. Never execute their host code.

## Decisions

* REM_BLOCK accepts no argument or the exact DOCUMENTATION heading (case insensitive like existing commands); END_REM remains argument-free. Arbitrary headings are not established by the reference.
* Seven documented suffixes POWERSHELL, BATCH, BASH, JAVASCRIPT, PYTHON, RUBY, HTML give fourteen block-only aliases. They end with the corresponding unsuffixed END_STRING or END_STRINGLN, as the official repository examples show. Cross-family terminators reject. Suffix-specific END_STRING*_LANGUAGE is literal text, not a delimiter; using it without the required unsuffixed close fails as unterminated. Preserve Stage7 literal prefix rules. Reuse Stage7 whitespace, literal-line, single-pass DEFINE then EvilDuck variable interpolation, Enter and scheduling rules. No inline alias or interpreter.
* EXTENSION name / END_EXTENSION transparently encloses ordinary code. VERSION is nonexecutable dotted-decimal metadata, optional, once before noncomment content inside a wrapper. Restrict names to the existing 32-byte identifier grammar, at most16 unique included extensions; disallow nesting, duplicate names and crossing function/control/preprocessor boundaries. These name/version/nesting limits are explicit safety/profile constraints where the prose does not establish general grammar. No online version checking. An extension body can contain functions, global variables, constants, conditionals and loops.
* IF_DEFINED_TRUE label and IF_NOT_DEFINED_TRUE label accept one valid canonical DEFINE label; ELSE_DEFINED and END_IF_DEFINED take no arguments. Undefined is false. A tested defined label must contain exactly TRUE or FALSE after whitespace trimming. Arbitrary text, arithmetic truthiness and recursive DEFINE evaluation are not established and fail diagnostically rather than guessed. Untested text constants remain valid.
* Collect included DEFINE declarations and decide inclusion in physical source order during the existing first cooperative pass. Definitions in excluded code have no effect. Forward definitions remain globally substitutable in included ordinary statements after collection (existing compatibility), but do not retroactively change preprocessing decisions. Official examples define flags before use; forward preprocessing and recursive values remain reference uncertainties. No fixed-point passes or recursive macros.
* A fixed8192-line inclusion bitmap (1024bytes) freezes decisions for the subsequent symbol inventory, validation and runtime passes, including arbitrary function/loop seeks. Eight preprocessor frames are independent of the eight IF/WHILE frames. No whole-file text/AST/cache or unbounded interval table. Read every excluded line through the same bounded reader, preserving physical diagnostics and storage faults. Preprocessor directives never reach the runtime scheduler or REPEAT history.
* Within excluded regions ordinary unsupported statements and runtime IF/WHILE/function syntax are not semantically validated or inventoried. Comment/text modes and their terminators, extension wrappers and preprocessor nesting are still structurally validated. Directive-looking text inside literal/comment bodies cannot change inclusion. A conditional must not split a comment/text block; lexical modes determine boundaries. Any remaining selected runtime structure is validated before HID. Expansion cannot manufacture structural directives, wrappers or text/comment delimiters.
* Canonical LED_R, LED_G, LED_OFF map to solid red, green, off on the single existing RGB pixel, obeying the existing user disable-LED setting. They suppress subsequent default idle/status updates for the current run, without changing legacy LED RGB semantics. Errors retain the established red-error priority; a new script restores normal defaults. No independent LED channels, blinking/storage status variables or button features are claimed.
* Newly recognized source/metadata/LED/alias names join the existing reserved-function-name policy. A function cannot shadow a command, even when invocation parentheses would disambiguate it; this is a deliberate compatibility restriction for previously user-defined names.
* Preserve Stage12 unknown lock-state evidence, unsupported internal variables and documented core3.3.0 HID routing limitations unchanged. Preserve partitions, PSRAM disabled, Arduino Micro and migration tooling.

## Verification plan

Production-source mocked suites cover fourteen aliases and exact terminators, headings, extension/version validity/duplicates/bounds, true/false/undefined flags, ordered definitions, excluded unsupported/variable/function/storage/HID code, nested preprocessing/boundary+1, expansion structural protection, physical line diagnostics, all source encodings/limits/read/seek faults, active and excluded control/function integrations, cooperative cancellation/backpressure and LED priorities. All prior suites and Stage9 observations run under ASan/UBSan; observations updated only where newly supported features change actual behavior. Compile the pinned16MiB core3.3.0 profile cleanly and compare binary/RAM/stack storage to Stage12. Allocation probes distinguish no-C++-new fixed-state operations from existing String allocations. Physical output/storage/LED and High Sierra behavior remain unverified.
