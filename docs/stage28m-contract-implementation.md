# Stage28M memory transport contract implementation

This is an isolated derived copy of Stage28K, not a production backend. `journal_driver.cpp/.h` retain the unchanged public Program/CompileSession/Bridge/Planner pipeline and authoritative Bridge admission/ack deltas. `synthetic_transport.cpp/.h` supply tagged fixture observations, not a SDK shim. No parser or private next-event inspection was added.

## Boundaries and identities

Driver S/E/R retain Stage28K meanings: session, admitted source event, report action. Delay has E but no R/Q; sync/setup/drain have E=0. Transport C/Q are checked uint64 lifetime/submission identities. The mock allocates and publishes Q with `(C,S,E,R)`, immutable bytes and outcome before any early notice or hook is possible. No callback creates Q by reading the current slot, equal bytes or a pointer. A test helper snapshots the already-created mock transfer to schedule its authentic model notice; a real tokenless callback cannot use that helper as correlation.

`Transport::poll` (`synthetic_transport.cpp:45–67`) returns Accepted only for the current report with success, independent retirement and valid binding/action eligibility. Matching current identity and byte shape are separately checked. Queued observations are copied through four fixed slots; `processOne` consumes at most one per owner step. Notice arrays retain input identities/metadata and classification. Full observation publication sets an independent sticky overflow flag; it cannot turn a dropped event into retirement. Actual transfer history is finite and never overwritten.

A poll with outstanding Q returns Retry without resubmitting. Definitely NotSubmitted retires that Q; a later bounded attempt allocates a fresh Q for the same R. Ambiguous outcome/failure/invalid current notice faults and quarantines. Early completion is processed on a later owner step; completion contradicting NotSubmitted faults. Every Sink invocation, including pending polls, consumes the unchanged Planner budget. Existing ceilings remain Planner 256/30,000 ms; Runtime 10,000 steps/100,000 ticks/30,000 ms; compiler 65,536 steps. Equality times out; wrap test uses uint32 elapsed subtraction. These are not real pacing/RTOS measurements.

Framing happens once: raw payload eight bytes, fixture report mode ID1 prepends `01` for nine bytes; explicit fixture ID0 framing is eight bytes. Instance0/endpoint0x81/protocol are **test bindings**, not measured descriptors or an approved real endpoint. The real raw API takes raw8 + separate ID, not preframed9 + ID.

## Source, setup and owner execution

`Driver::start` (`journal_driver.cpp:46–51`) rejects any queued request, executing setup request, non-Ready Planner, unresolved transfer or invalid lease. Rejection leaves Runtime Prepared and identities/work intact. Eight queued requests map into 128 fixed disposition entries. Successful admission is not execution: entries move Admitted→Executing→Executed only once the setup action is accepted/Ready; invalid setup moves Rejected; terminal cleanup explicitly marks unresolved entries Cancelled. Idempotent setup requiring no new report can resolve directly through Planner's documented behavior. Direct hold/release still cannot cross a pending Planner action.

Owner `step` handles sticky urgent flags before source progress, processes one notice, then at most one request/Bridge step. Callback-role publication only copies a bounded observation or flag. Submission-hook reentry into driver mutation and transport process/fence/rebind/poll is rejected before mutation. This is a deterministic role/reentrancy model, **not threads, portMUX, ISR synchronization or a secure capability system**. Fixture configuration/hook methods are test controls, not production API entry points.

Cancellation stops source before its next ack tick; old current Q can complete/retire only. Success without retirement retains its buffer; late retirement does not create Accepted for cancelled E. A cancellation requested after an already committed source ack cannot undo it (B06). First driver/service faults are preserved within their lifetime; an explicit reviewed mock rebind begins a fresh service epoch, while the driver retains first-fault diagnostic history. No automatic resume.

## Lifetime, drain and fences

A single operational slot refers into retained transfer evidence, keeping framed bytes immutable until acceptance/retirement or cancelled retirement. Cancelled retired work releases the slot; genuinely old notices remain classifiable without using payload identity. Explicit mock `fence(C)` certifies transfer and observer quiescence, discards that fenced callback backlog, invalidates binding, and permits separately requested rebind. It is injected evidence, **not inferred from reconnect, an empty queue, zero bytes, end(), or destruction**.

Fresh neutral drain E=0 may run only after old resources retire and binding is valid. It must receive new success+retirement for a fresh R/Q. Drained gates a new explicitly begun session, which still requires its own sync. No global cancelled-source flag suppresses the management drain. `canReclaim` also requires the observer certificate, terminal/idle/drained state and no active compiler. It denies permission to an owner to destroy/reconstruct an unsafe context; C++ itself cannot prevent arbitrary misuse of delete/placement-new. Each fixture captures outcome evidence first, then explicitly requests owner cancellation and injects a transfer/observer fence before reclaiming either Driver or stand-alone Transport. Destructor only cancels compiler/Bridge and never invokes a transport submit. A future persistent coordinator must preserve counter continuity across any authorized reconstruction; tests use separate independent fixture lifetimes.

## Fixed storage and retained limitation

Host GCC measurements: Driver **182,832 B**, containing Transport **147,856 B**; Transfer80 B, Notice56 B, RequestEvidence6 B; Program6936 B, CompileSession2416 B, Bridge5056 B already embedded (Runtime/Planner not counted twice). Driver growth from separately rerun K's34,128 B is148,704 B: Transport plus848 B request-disposition/index bookkeeping. These are **host object layouts**, not Xtensa/static firmware RAM or available device headroom.

Capacities: one outstanding/quarantined slot; ordinary queue8; observations4; setup evidence128; reports256; intents128; transport attempts1024; observation evidence1024; configured submission plans16. Transfer evidence alone uses1024×80=81,920 B. All journals are test-only fixed arrays, with visible refusal/fault at capacity. B12 proves attempt/notice evidence exhaustion retains unresolved resources instead of overwriting them. Healthy C++ new probe observes zero calls in compile/run/drain; it does not measure libc/SDK allocation, error paths or physical heap.

The conservative E-capacity guard is retained. L20 executes its finite boundary and256 retired operational-slot uses; final Delay/non-event progress through a pre-admission API is **BLOCKED/UNSELECTED**, not PASS. No changes to language_preview or unsupported modifier-source/INJECT_MOD/RESET/locale/Unicode contracts. Stage28L's proposed1,536 B production budget is not a measured layout and is not the size of this evidence-heavy test driver.
