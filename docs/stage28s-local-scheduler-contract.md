# Native Route B contract

**Native only. LOCAL_SCHEDULER_DONE describes local scheduler phases and backend submission results. It never certifies USB transfer success, safe controller retirement, neutral host state or application delivery.** No unchanged Bridge/Planner is used under a weaker meaning. Unchanged Program, CompileSession and Runtime core.cpp/.h compile into the harness alongside real com.cpp and its production parsing/text/control dependencies.

## Scratch-only, default-off seam

`prepare_sources.py` checks exact input SHA, patch SHA, fresh output and exact patched SHA; patch applies with `--fuzz=0` only in a new external directory. `scheduler.patch` gates all new behavior with EVILDUCK_NATIVE_SCHEDULER_ROUTE_B. Definitions in seam.inc and scheduler_seam.h are new native fixture files, not SDK code. No installed or tracked production source changes. Final command/source hashes are in source-and-patch-manifest and test-results.

`acquire` requires idle unowned scheduler, no pending clear/persistent keys, valid US locale/HID mode, unused session namespace. It creates a monotonic64-bit local session before requesting a fresh clearing submission; no existing callback is replaced. Lease makes `com::busy()` true even between operations, so actual `duckscript::run()` rejects before mutation. Native mode guards legacy begin/end/send/sendText/executeNow and callback registration; current production callback pointers remain retained and suppressed, then work again after detach. Only one serialized native owner calls update. This is not a cross-task or raw-USB exclusive lease.

`character`/`key` have typed Rejected/Admitted results. Before scheduling they allocate a checked monotonic64-bit operation ID into one retained Result slot. No second operation until the terminal result is consumed. Equal characters do not identify operations. The actual real `startText`/`report`, jitter seam, Press→5ms dwell→Release→Finish execute; native literal characters bypass interpolation, parser and trimming. Native default delay/jitter are zero without changing saved settings. Existing global random range/jitter and prior scheduler default delay are snapshotted/restored around begin/end cleanup. Required5ms scheduler dwell remains real. Legacy behavior resumes after detach.

At actual scheduler Finish the original admission's Pending result becomes Done; actual fail becomes Error. These are synchronous scheduler-local publication sites while the one operation remains owned, not USB callbacks relabeled from whichever transfer happens to be current. Result is copied/polled, not delivered through production global callbacks. There is no new asynchronous callback queue. The result slot stays stable until matching consume, cannot wrap IDs, and cannot be overwritten by a second request. Test-only inspect checks copied observations against that immutable local result and never writes Done. Wrong/stale/repeated observations cannot acknowledge source; this does not simulate actual late USB callbacks.

## Adapter behavior and bounded storage

Adapter captures a stable source in owned8193-byte storage32 bytes per step; retains bounded Program, CompileSession and Runtime. Compiler runs its unchanged two-pass limits before any backend operation. Runtime Sink admits one Character/KeyTap once, returns Retry while matching local result is Pending, then consumes Done and returns Accepted once while eligible. No retry of an admitted operation. Event equality is only an integrity check. Delay is immediately locally accepted into unchanged Runtime's uint32 timer; it is never sent to com as another Delay. Source errors retain runtime line information; first adapter fault remains latched even if cleanup later fails.

One step does at most one source-read, compile step, or one com update plus one Runtime tick (not a claim of one total instruction). No sleep/busy loop or recursive Runtime call is added. Native callback-time start/step is rejected, cancellation is deferred until the current scheduler call returns. Each local result is a fixed copied slot; no unbounded report/request queue. Public prepare/start reject active or quarantined state before mutation. Adapter exposes no Prepared owner/setup API. Prior local action during Syncing fails before Runtime starts, preserving K01's barrier principle.

Limits: source capture65536 turns including Retry; CompileSession65536 existing steps. Per pending output1000 turns or1000 caller-ms, per sync/clear1000 turns or1000 caller-ms, equality exhausts. Caller supplies one uint32 timebase matching mock millis; wrap assumes short periodic gaps. Runtime retains10000 steps/100000 ticks/30000ms, fixed IR/arena/call/token caps. These do not prove real recursive mutex/SDK/controller calls bounded; their real blocking behavior is outside this native scope.

## Cancellation, loss, clearing and restart

STOP_PAYLOAD produces the unchanged Runtime's Cancelled terminal state. Completion, STOP, cancel, runtime/backend error revoke admissions and call actual com endScript through the seam once. Native deferred cancellation is handled before the next Runtime tick. No late success for a cancelled source is accepted. Existing endScript cancels pending work and requests zero where keys were owned; seam requests a fresh zero when no such request was generated. clear status is separate from source result.

While clearing remains pending, lease/context is retained and restart rejected. Successful local zero submission permits detach; it is **LOCAL_CLEARING_SUBMITTED**, not host release or strict drain. Every new session requests a fresh synchronization zero. Deadline/ambiguous clearing leaves Quarantined and owner retained, never automatic recovery/arming. Adapter destruction does not send reports; owner must drive cleanup or retain quarantine. Typed result state is global scratch scheduler storage, not a callback pointing into reclaimed adapter memory.

HID/layout invalidity refuses initial acquire and ends an active session; production's intentional skip behavior is not acknowledged as output here. Disconnect never resumes/replays automatically. Native backend distinguishes known pre-admission refusal, accepted submission, known failure and ambiguous outcome. Ambiguous simulates a possible accepted frame before a false result; fixture poisons further lower submissions, keeping cleanup unresolved. Native error observation prevents a second normal restoration attempt after ambiguous/error results. Existing production false/retry behavior remains unchanged outside opt-in; actual backend cannot necessarily classify all physical ambiguity as this richer fake does. No physical fault recovery is claimed.

Journals contain emitted queue attempts, times, local diagnostic IDs and scheduler phase; poison suppresses subsequent lower attempts before journaling. Diagnostic IDs are not USB correlation. Legacy traffic after lease detach has session/op0. Copy/queue/stack/controller/OS/app acceptance remain distinct. Existing production callbacks, USB state, stored settings, prefixes and language compatibility are not independently validated by native mocks.
