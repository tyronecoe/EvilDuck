Default/opt-in-off behavior must remain compatible if a future DCD change is authorized. Stage28P adds **no semantic DCD patch or new controller opt-in**: driver source is exact; common I/O adaptation is native-only. No production source, source-language behavior or installed dependency changes. Current native proofs support a design gate, not an implementation-ready hardware certificate.

Next narrow proposal: verify an official-source-backed per-endpoint interrupt/disable/flush model and producer-fence contract, then test whether an immutable-origin record can survive all old IRQ/publication cases. Keep core/FreeRTOS integration, target ABI/reproducible SDK rebuild and supervised physical questions as separate authorizations. Do not begin Stage28Q automatically.
