# Transport choices from actual source

**Recommendation pending owner selection: B, an opt-in Runtime-to-existing-command-scheduler route, initially ownership-free US text/named keys.** Keep the strict A contract intact and blocked. No adapter or alternate contract is adopted here. Evidence IDs and exact SHA/spans are in `stage28r-source-evidence.json`.

## A — Strict correlated success plus retirement

Producer: unchanged Preview Bridge/Planner (`bridge.cpp:35–61,71–92`, `keyboard.cpp:68–82`). Acceptance: Stage28L current correlated complete successful IN action plus safe retirement, epoch/framing and eligibility. Press/restoration are separate reports; source ack follows both. Cancellation removes source eligibility but retains unresolved resource lifetime; explicit fresh drain cannot borrow old zero evidence. Restart needs a new reviewed lifetime and current drain.

Pieces exist experimentally: M identity/journal/barrier, O real stack/class opt-in patch with fake tagged DCD, P actual selected DCD under native assumptions, Q conditional retirement model. Missing: authentic raw-origin correlation, documented stop/flush/IRQ fence, bounded RTOS claim and complete producer lease, coordinated source-to-object/ABI integration, actual host/physical validation. Shared semaphore is not a substitute. Dependency changes would be coordinated stack/class/DCD/core work with separately verified isolated builds; none installed. Cost/risk highest. Retain blocked; no more generic green models establish the missing physical premise. Vendor support packet is useful to this option.

## B — Keep production USB backend unchanged; extend language above scheduler

Actual boundary: `com.h:5–26`, `com.cpp:392–451,454–624` exposes beginScript/send/sendText, busy, done/error hooks and cooperative update; current `duckscript.cpp:276–310,333–400` owns File, preflight and calls it. It is not `hid_backend::pressReport`, which is legacy/blocking, nor a Bridge report sink.

`executeNow` true at451 means a live command was scheduled, not finished. It rejects script ownership. Script `send` and `sendText` return void and ignore nonowned/busy submissions. Finish at622–623 reaches Idle and script callback only after its local phases/default delay; failures also reach Idle at366–373, so busy=false alone is NOT success. Callback slots are global; cannot take them away from the active production engine. Need exclusive execution mode/owner, existing-script admission rejection, one retained pending event and explicit done/error latch. Callbacks mark state only; do not recursively tick Runtime. A minimal future additive typed admission/result seam may be necessary to prove rejection before work; that would be a separately reviewed com-layer change, NOT a new USB transport.

Local report path: com Press→5ms dwell→Release (`550–560`), text/dead-key stroke scheduling (`562–585`), jitter (`117–129`), Finish/default delay (`602–624`). Backend beginReport merges persistent ownership then calls queueRaw (`272–286`); queueRaw checks mount/readiness and calls `tud_hid_n_report` (`254–261`). TinyUSB `hid_device.c:113–131` claims, copies into its fixed class buffer with ID prefix, calls usbd_edpt_xfer; `usbd.c:1389–1421` sets busy then returns DCD result, clears busy/claim on false. Selected DCD `601–628` records cursor/length and schedules packets, not host acknowledgement. Ordinary stack busy/claim is what already owns the copied class buffer; B does not invent or prematurely recycle an application-owned USB descriptor.

**Proposed B acceptance**: current uniquely admitted local scheduler operation reached successful Finish after required press/restoration *submission results*, while still eligible. Record this as LOCAL_SCHEDULER_DONE, not Stage28L Accepted. Runtime Sink's Accepted would be explicitly bound to that weaker local meaning only in the newly selected execution route; unchanged Bridge retains its old contract and is not reused for this route. Delay is accepted into Runtime's own clock and never sent as another com delay. Proposal starts with default delay/jitter zero for deterministic opt-in smoke, with explicit future policy to preserve configured production behavior outside that mode. Do not reset settings or global defaults silently.

Ordering/ownership achievable at application level: one pending source event, exclusive com session, serialized completion/error, next tap only after local prior restoration accepted. Initial subset excludes source HOLD/RELEASE and external Prepared owners: production single global Owned/idempotent holds cannot implement preview's four-owner/fresh-union contract. Preview supports these syntaxes in memory; an opt-in capability preflight must reject them before any output (existing ownershipCommands supplies one check). No raw report injection, no dual Planner/backend ownership. HID-disabled production text/keys can intentionally complete without output (com startLine146–154 and update563,591); the opt-in route must require HID enabled at admission and treat loss/change as failure rather than acknowledge a skipped action. Existing sendText still interpolates via duck_vars at151: use one literal Character event at a time and prove dollar/whitespace handling, or separately review a literal-only seam; do not batch text and change its meaning. This is a narrower opt-in path, not a drop-in replacement or proof all preview programs work.

Cancellation: stop Runtime, revoke future command admission, call existing endScript once, preserve backend clearing and poll until *local clearing submission* is no longer pending. No success ack for cancelled source, no resubmit of an accepted command. Disconnect/failure ends session; no automatic resume/replay. No reuse of an unresolved application callback context; keep it persistent until old local owner is detached. Start/restart stays rejected while clearing/unresolved. Existing endScript cancels pending text/delay/repeat and requests release; disconnected host state remains unknown. Local zero submission is not correlated neutral completion or host release.

Limitations retained: loss or ambiguity after submission, no application-level delivery ack, possible partial text before error, busy/claim/DCD source-to-object uncertainties, underlying locks/loops may block, single ownership ledger, host layout/protocol assumptions, no bounded end-to-end transport guarantee. Existing backend retries on false for validated fixed reports. Future adapter must not add blanket retries of already-admitted work or post-submit ambiguous errors. It must distinguish readiness refusal from failure/unknown and quarantine ambiguous local state. Require bounded pending-operation attempts/deadlines and first-fault capture at the new application seam, without claiming the underlying SDK call or recursive executor lock has a proven hard bound. Existing normal behavior's limitations are disclosed, not solved by weakening the words Accepted or retirement.

Smallest next implementation: native memory-only contract around actual com production-source scheduler and unchanged Runtime, with a mocked backend; deterministic admission, one-event pending latch, local done/error, cancellation/clearing, Delay ownership, and capability rejection. No USB/core/DCD modification. This can proceed independently of vendor answers AFTER owner selects B and separately authorizes that scope. Current source blocker is absence of a typed uniquely-owned admission/result boundary; current API/global callbacks need a reviewed exclusive seam. Reentry, live web/CLI and startup opt-in require production integration review later.

## C — Public raw snapshot adapter, different from B but not preferred

A new adapter could call `tud_hid_n_report(0,1,payload,8)` directly under a single reviewed owner, using Planner reports rather than com's command/merged ownership. This is materially different: preserves Planner snapshot/four-owner semantics and moves dwell/locale/default-delay policy into the adapter; bypasses existing com phases. Raw true means copied/claimed/submitted through selected stack, not correlated completion or retirement. Core `USBHID::SendReport` is not a better alternative: `USBHID.cpp:331–374` uses a shared semaphore/mutex, waits, and explicitly discusses late/extra gives; false after submission may mean timeout. Never map that false to safe resend.

C would need exclusive exclusion of every legacy/raw producer, binding/protocol/ID review, prompt refusal classification, buffer ownership and cancellation/neutral policy, bounded timing, locale translation, startup gating and native actual-stack tests. Stage28O is NOT installed or adopted. C cannot honestly retain L's strict predicate through current public APIs. It duplicates scheduler behavior B already has and still inherits lower-layer ambiguities/locks. Smaller than A only under a deliberately weaker admission contract, but larger integration surface than B. Not recommended for first language milestone.

## Decision table

| Route | Acceptance evidence | Dependency scope | Native next check | Main blocker |
|---|---|---|---|---|
| A | Tagged successful transfer AND retirement | Coordinated core/stack/DCD/OS changes | Authoritative sequence plus producer fence review | Missing real controller/IRQ guarantee |
| B (recommended) | Exclusive current command's local Finish after submissions | None at USB layer; future opt-in scheduler seam | Actual com + Runtime with fake backend | Owner contract choice, typed admission/lifecycle and semantic subset |
| C | Public report copy/submission only | Future firmware raw-snapshot adapter; no assumed vendor patch | Actual stack refusal/lifecycle plus Planner | Duplicate scheduler policy and complete producer exclusion |

No option proves host delivery. B is practical because it reuses existing behavior, not because it secretly supplies A's extra guarantees. If owner requires A for every deployment, B/C remain ineligible. Conversely, choosing B need not await every A premise. Physical deployment gates remain separate whichever route is selected.
