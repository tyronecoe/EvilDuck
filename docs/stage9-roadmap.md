# Stage 9 ranked development roadmap

This is a reviewable specification, not authorization to implement Stage10. Stage9 changes documentation/test evidence only. Effort L/M/H and priority P0–P3 are comparative estimates; no calendar promise, precise completion percentage or fixed final stage count is justified. Each milestone needs its own approval, regression/build report and branch. Preserve plain streaming, single evaluator, bounded stacks, core3.3.0, PSRAM-disabled16MiB profile and migration safeguards.

## Recommended first Stage10 scope

Implement **truthful and bounded USB-storage mode operation** before layering internal variables or persistent ownership onto it. The failing-MSC production probe is direct evidence; callback offset/seek/range paths need equivalent production-source tests, not just parser acceptance. No new language features are needed in this first milestone. Preserve current supported mode aliases but report real initialization failures. OFF's current gate behavior must remain clearly labeled until actual USB personality transitions have been designed, rather than silently claiming detach.

Acceptance set: failing/successful MSC startup and retry; exact nonzero callback offsets; start/end/beyond-end ranges; overflow; seek/partial I/O/card removal failures; cancellation and bounded creation; simultaneous script/live-command ownership; complete Stage1–9 tests with sanitizers; clean core3.3.0 build; measured static/stack/heap changes; no altered partitions/PSRAM, real HID, hardware access or Micro edits. Only after review proceed to persistent key ownership. If user chooses HOLD/RELEASE first instead, isolate mode defects as an explicit prerequisite/deferred risk and retain this evidence; neither path is implemented now.

## High-value missing tests (not fictitious passes)

* Compile actual MSC callbacks against fault-injecting SD/File mocks; lba/offset/length, seek, short writes, create-full/removed card, descriptor/media lifecycle. Stage9 production attackmode probe covers failure status only, not these callbacks.
* Compile real storage adapters and canonical path rules rather than mock parseRef shortcuts; empty READ versus failure, file growth/huge reads, same-size modification between preflight and runtime, cooperative file writes. Design an explicit mutation policy for web file/settings/OTA callbacks during execution.
* Future held ownership while auto-shift/dead-key STRING runs; six-key saturation; runtime error/preflight failure/restart/cancellation; transport refusal while releasing last key; press order and repeated held-key requests.
* USB HID OUT event sizes/order/unknown initial state, repeated same state versus change, stale replies after disconnect, missed replies, save/restore acknowledgments and bounded wait cancellation.
* Reference compiler differential corpus: unsigned truncation, exponent associativity/zero, short circuit with global function mutation, implicit returns, macro replacement ordering/structural values, tabs/trailing text. Mark unavailable expectations unresolved.
* Default-delay/REPEAT after every command class, functions/void calls/empty blocks and skipped branches; meaningful different operands rather than dozens of trivial duplicate labels.
* Runtime heap/task-stack/web/storage concurrency tests on the actual board after approved migration, plus physical lock-state and descriptor analysis. Host allocation probes do not replace these.

## Physical validation and migration gates

Hardware work is a separate authorization. Stage9 did not reissue or execute write/erase/OTA commands and does not make any new firmware migration artifact. Existing protected NVS/layout/file-level SPIFFS migration safeguards remain in force. User-confirmed16MiB and original full/partition backup hashes must be rechecked against local files before any operation. Old SPIFFS0x170000 must not raw-relocate into new0x160000; the separately user-verified repacked image and seven-file roundtrip remain required. Recovery through ROM download and tested port/cable/power prerequisites must be available; no full-chip erase or padded merged image for normal migration.

First actual-host scripts should be reviewed visible TextEdit output on High Sierra10.13.6 with matching input source, no shell/host command opening. Establish plain US output, then DE punctuation/dead keys/Option, F/navigation/keypad, modifier releases and STOP timing. Test SD/SPIFFS/runtime loops/functions/text under web traffic and measure heap/stack. Finally validate lock reports and USB identity/mode transitions as separate experiments with recovery prepared. Successful software builds and exact mocked HID bytes do not authorize or prove any of these physical behaviors.
