## Reference and explicit compatibility decisions

* $_RANDOM_INT is a read-only uint16 fresh value on each evaluated reference; $_RANDOM_MIN/MAX are writable uint16, default0/9. Interpret documented minimum/maximum endpoints inclusively. Equal bounds yield that value without entropy consumption. Temporary reversed bounds may be assigned (so either bound can be changed first), but drawing from reversed bounds errors. Values outside0..65535 follow the existing expression/literal overflow rules; no second evaluator.
* Raw device entropy comes from esp_random(), with no cryptographic quality claim. No guessed seed.bin format, implicit file writes, seed persistence or Hak5 PRNG equivalence. $_RANDOM_SEED remains reserved unsupported. Host-only source injection permits reproducible/scripted streams and a seeded test generator, not a new DuckyScript seed command.
* Range selection uses rejection sampling over32-bit draws to avoid modulo bias. A maximum32 attempts prevents an adversarial/stuck source from stalling; exhaustion fails with a source diagnostic. No dynamic table/AST/queue. Settings reset at script start/end (including STOP/error); live settings persist until executor reset. RNG source state is device-owned and is not a fictitious per-script seed.
* Support RANDOM_LOWERCASE_LETTER, RANDOM_UPPERCASE_LETTER, RANDOM_LETTER, RANDOM_NUMBER, RANDOM_SPECIAL, RANDOM_CHAR. Each emits exactly one character through existing locale/scheduler output. Sets: a-z, A-Z, both, 0-9, !@#$%^&*(), and their72-character union. The table's space between letter groups is treated as visual formatting, consistent with the quick reference's letter/number/special description; no SPACE member invented. RANDOM_CHARACTER appears only in explanatory prose, not the command table; retain unsupported until confirmed. No standalone RANDOM_STRING/length syntax is documented; construct bounded strings with existing loops/functions. Random scancode properties remain unsupported pending encoding evidence.
* Jitter variables $_JITTER_ENABLED (Boolean0/1 only, defaultFALSE), $_JITTER_MAX (uint16ms, default20, zero allowed). Choose uniform inclusive0..MAX extra delay before each planned transient press, including Enter, chords, dead-key strokes and inline modifier injection. HOLD injection uses the same prepress wait; RELEASE/RESET/STOP/cancellation releases never wait for jitter. Repeated idempotent HOLD may consume a scheduling sample but produces no extra report. This prepress lower-bound/additive timing policy is explicit because the reference does not establish a minimum, dwell timing or default-delay composition. Existing5ms dwell/transport/default/explicit delays remain independent; MAX bounds added jitter, not total host cadence.
* Draw once when preparing an event, before USB retries. Wait uses the existing wrap-safe cooperative clock phase; no whole-string delay, blocking sleep or dynamic report queue. Refused/retired press plans do not redraw; canceled plans can consume entropy without host output. Lock restore retains deadline/evidence validation and jitter never delays safety release.
* Preflight/type checking never samples randomness. Syntax resolvers expose metadata; compiled expression operands sample once when executed, with values preserved across function suspension. Legacy no-THEN/bare-variable condition adapters must not read volatile numeric operands while probing types. Existing eager logical evaluation remains documented, not secretly changed to short-circuit.
* INJECT_VAR and RESTART_PAYLOAD research only. Docs establish scancode input (not integer-to-text) and restart-from-beginning but not independently verifiable packed encoding, seed/user/internal/USB reset persistence. Propose separate reviewed milestones; do not implement them or descriptor randomization.
