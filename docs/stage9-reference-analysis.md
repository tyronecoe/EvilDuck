## Behavioral differences with valid official scripts

### Expressions and variables

One precedence parser emits bounded postfix instructions; all assignments, numeric command arguments, IF/WHILE and returns use it. Low to high precedence: `||`, `&&`, `|`, `&`, `== !=`, `< <= > >=`, `<< >>`, `+ -`, `* / %`, `^`, grouping/atoms. Binary operators associate left except `^` right. Function operands execute left to right once, capturing preceding variable operands; logical evaluation is eager. `FALSE && next()` still calls `next()` when the containing condition is eligible. Ineligible ELSE IF/inactive parent conditions do not execute functions. Official pages require grouping to establish precedence but do not provide a complete unparenthesized precedence/side-effect contract. Explicit grouping remains the portable recommendation; short-circuit compatibility is unresolved, not proven defective.

Variables are unsigned16 globals, TRUE=1/FALSE=0 and every nonzero value is true. Arithmetic wraps modulo65536 after operations; decimal/hex literals above65535 fail. Division/modulo zero fail; shifts outside0..15 fail; power uses bounded modular exponentiation, including 0^0=1. No undefined C++ shift/overflow behavior is required. The reference identifies uint16 and lists operators, but does not conclusively establish all intermediate truncation, exponent overflow, shift-width, invalid-literal or zero-division behaviors. Modulo's prose says signed remainder despite unsigned variables; current safe unsigned result is documented policy. Hex is documented; C unary operators, XOR, `+=` and `++` are not established by these fetched tables. The quick-reference “Augmented Assignment” section actually demonstrates `VAR $FOO = ($FOO + 1)`, which already works; do not turn that heading into a fictional missing `+=` feature.

Same-type VAR redeclaration is allowed. Assignment to undeclared variables fails. Functions share globals; preflight gathers potential declarations conservatively and validates both branches. A variable declared only in an inactive branch may pass syntax validation and fail at its first runtime read. Duplicate definitions, changed numeric/text type, symbol exhaustion and limits fail safely. Numeric-variable names accept letters/digits/underscore following `$` (including first digits); function names reject initial digits and supported command/modifier collisions. The reference's naming guidance is less precise than a complete identifier grammar. Canonical internal variables are completely unbound: reads normally fail undefined, but `VAR $_JITTER_ENABLED=TRUE` creates an inert ordinary symbol and does not enable jitter. This is a high-impact false impression of support, not actual built-in-variable functionality.

### DEFINE and preprocessing

`#LABEL` replaces any occurrence; bare labels replace complete whitespace-delimited words, including tabs as an EvilDuck extension to the reference's spaces. DEFINE statements are exempt from substitution. Expansion is single-pass, longest matching label, collected before execution, globally available regardless of subsequent runtime branches. Replacement results are not recursively scanned. Duplicate labels reject. A 16-entry table and2048-byte value pool bound definitions, and expanded statements/data are capped at512 bytes.

The official constants page explicitly permits any valid DuckyScript syntax as a value, exemplified by a command-valued `#FINISHED_PAYLOAD_LED`. Nonstructural command-valued expansion works today. Structural markers/THEN/function invocation cannot be created by expansion; this is a deliberate preflight safety divergence from the broader prose, not full DEFINE conformance. Text blocks recognize literal delimiters before substitution so constants cannot escape into execution. Recursive expansion is not required by the documented DEFINE exclusion example. Overlapping-label/redefinition/order details without reference confirmation remain policy, not independently matched results.

`IF_DEFINED_TRUE`, `IF_NOT_DEFINED_TRUE`, `ELSE_DEFINED`, `END_IF_DEFINED` are wholly missing. They are compile-time inclusion, not ordinary IF. Inactive runtime branches still undergo semantic preflight; therefore `IF FALSE` cannot substitute for excluding unsupported code. A future streaming preprocessing pass must handle excluded lexical regions/definitions before semantic validation, preserve physical line numbers, enforce limits and avoid an unbounded cache.

### Conditions, loops, functions and resource policies

Canonical IF/ELSE IF/ELSE/END_IF and WHILE/END_WHILE work with a shared depth8 typed stack, including function boundaries. Bare legacy IF atom/equality and alternate terminators are explicit EvilDuck extensions. Loop state stores offsets/counters, not entire source blocks. Runtime-active WHILE body entries are capped at100000 per run, and1024 consecutive iterations without variable revision or command action trigger a stalled-loop error. Computation-only intentionally infinite loops can therefore be rejected; finite/action-heavy loops may reach the global budget. This is an intentional safety limit, not proof that semantic progress can always be inferred.

Functions are declared top-level with NAME(), skipped during sequential execution and called by statement or expression. Sixteen definitions, eight call frames and100000 total calls bound execution. Globals serve as arguments; no undocumented parameters/local scope introduced. Numeric/Boolean returns use the same evaluator. Explicit/implicit void is valid for a statement call but value-consuming void fails rather than silently supplying0. Reference behavior for implicit value returns is unresolved. Bare top-level RETURN is a legacy Enter alias, contextually distinct from a function return. Recursive calls may exhaust either the call stack or shared control frames; budget failures and seeks release ownership and terminate safely. Cancel/STOP is checked between bounded updates, not recursive whole-script execution.

### Text and comments

Inline STRING/STRINGLN trim trailing whitespace, consistent with the explicit basic injection prose. STRING blocks strip leading spaces/tabs and concatenate body lines without separator. STRINGLN blocks remove exactly one initial literal tab and add Enter after every body line, including blanks; an empty block outputs nothing. Other indentation/trailing text is preserved. Documentation contains one mismatched END_STRING terminator for STRINGLN and rendered space indentation despite first-tab prose; matching terminators and prose govern current implementation. Precise whitespace supplied by expansion/default-delay-per-body-line edges lack a separate reference compiler test.

Official embedded language forms for BASH/BATCH/HTML/JAVASCRIPT/POWERSHELL/PYTHON/RUBY behave like STRING/STRINGLN blocks; editor syntax highlighting/autocomplete is the additional feature. Both editions accept the syntax. These14 names are absent, not “Pro-only language features” and not evidence that a new embedded interpreter is needed. Screenshot-only alias terminator details should be verified before implementation.

Known `$identifier` decimal/text interpolation is an EvilDuck extension, including inside literal blocks. Unknown identifiers remain literal; replacements do not rescan. Official INJECT_VAR injects encoded scancodes; it is not a command to print decimal integers. The reference uses a TRANSLATE extension for decimal representation. A source body using `$x` as a host-language variable can be changed if an EvilDuck global of that name exists. This compatibility collision needs a profile/escaping design, not silent removal of working scripts.

REM works as an exact command. Official `REM_BLOCK DOCUMENTATION` rejects today because markers take no arguments, even though its bare form correctly suppresses fake commands. The new fixture proves rejection occurs before preceding valid output. Correcting the documented heading form is a localized high-value parser task.

### Timing, history and ownership

DELAY uses cooperative, wrap-safe timing. The current official delay page states a20ms minimum, while EvilDuck deliberately retains DELAY0/sub20ms and uint32 plain decimal compatibility; expression results areuint16. A new fixture proves acceptance, not physical timing. DEFAULT_DELAY/DEFAULTDELAY, WAIT, REPEAT/REPLAY remain legacy/EvilDuck compatibility behavior; the current official DS3 reference retrieved here does not establish every alias/history rule. Repeat history is last actually dispatched command or text body line, not skipped commands/structural markers/function declaration; n means n extra repetitions. No whole-block repeat invented. Default delay per text body line and re-expansion of variables can differ from a compiled payload model.

Transient keys are pressed/released through one eight-byte report (reportID1; modifier/reserved/six usages). Five-ms minimum dwell and retries bound output work. STOP cancels pending text/delay/repeat and prioritizes a deferred zero-report until transport ready. A disconnected host cannot receive that release while disconnected; mocks prove retry state, not host recovery. Persistent ownership, HOLD/RELEASE/INJECT_MOD and canonical RESET are missing; RESET means release/clear HID buffer, not reboot. Canonical STOP_PAYLOAD/RESTART_PAYLOAD are absent despite EvilDuck STOP working. Runtime namespace/profile changes must not erase historical release guarantees.

## Source-backed device defects and feasibility

### ATTACKMODE / MSC correctness

`attackmode::setStorage` sets its boolean before `usb_msc::begin`; failure only logs and `applyFromString` still returns true. The new production attackmode probe links the actual implementation with a failing MSC stub: requested STORAGE reports enabled although MSC is inactive, and a second request skips retry because the flag already matches. This is a demonstrated defect, not just a missing canonical feature. Fix error propagation and logical/actual state reconciliation before adding status variables.

The pinned ESP32-S3 qio_qspi SDK has CONFIG_TINYUSB_MSC_ENABLED=1. `MSCOnBoot=default` does not eliminate the manual MSC implementation. Arduino3.3.0 `cores/esp32/USBMSC.cpp:188–205` registers the MSC descriptor in its constructor; EvilDuck has a static MSC instance. Descriptors may therefore include MSC even when only HID injection is logically enabled. `.ino` calls USB.begin once; neither ATTACKMODE OFF nor setHid invokes USB detach/end. OFF is not canonical prevention of enumeration; changing media-present flags is not proof of changing descriptor personality. Verify actual enumerated composite descriptor/lifecycle physically later, after a mocked lifecycle design.

`usb_msc.cpp:37–56` explicitly discards callback `offset`, seeks only lba*512 without checking seek success, and accepts any callback bufsize without checking backing-file range. Arduino's callbacks supply offset unchanged. Source shows an incorrect addressing path whenever offset is nonzero, plus potential wrong-position I/O after failed seek. These are source-derived defects; they have not been reproduced on physical USB or isolated production storage callbacks in this stage. High-value missing tests must force nonzero offset, out-of-range lba/length, read/write partial return, seek failure, removal and concurrency. Do not call the source inference a executed storage corruption test.

The MSC medium is a separate4MiB `/sys/usb_disk.img` on SD, initially filled with zeros (not a valid formatted FAT volume). Creation synchronously performs8192 sector writes without cooperative yielding/checking each write. MSC does not expose payload folders or SPIFFS. No raw physical-device media modification was performed. OFF/dynamic descriptors, formatting, identity fields, save/restore modes and host activity tracking require explicit architecture work; merely adding parser names is insufficient.

### USB/status/host detection

Arduino3.3.0 USBHIDKeyboard.cpp:56–69 provides an LED output event path and onEvent callbacks. EvilDuck registers no listener; lock state/change waits and lock-state internal variables have no data source. Native ESP32-S3 USB OTG can support it; it is software missing, not board-inapplicable. Bound callbacks to a fixed event/state snapshot, handle unknown/stale host reports, and expose clear readiness/timeout semantics. macOS may not reflect every lock state and Num/Scroll behavior differs; never infer FALSE from no reply.

OS_DETECT/DETECT_OS(), TRANSLATE and ASCIIDUCK are source extensions, not native built-in functions. EXTENSION/END_EXTENSION/VERSION wrappers currently reject. Some extension bodies could run after stripping metadata, but each dependency must be audited: configuration-request counter, LED-reply state, INJECT_VAR/scancode encoding, globals/constants and table limits. Enumeration counts are heuristics, not authoritative OS identification. `$_OS` is extension-defined; `$_HOST_CONFIGURATION_REQUEST_COUNT` is device-backed and missing. Do not invent a host OS result to accept a script.

Randomization/jitter are feasible with ESP RNG and bounded scheduler state, but startup autorun random delay is unrelated to canonical per-read random variables, seed.bin, random HID/scancode commands, per-keystroke jitter or randomized USB descriptors. Deterministic seeded mock tests and defined entropy/range/read-only policies must precede any compatibility claim.

### Board / storage / host limits

The repository S3 schematic labels N16, native D−/D+ on GPIO19/20, SD CS10/MOSI11/clock12/MISO13, NeoPixel dataGPIO1, a reset/EN button and a GPIO0 bootstrap button. SD_ENABLED=38 is a truthy enable macro, not GPIO38 configured as a button. Firmware does not read either button. GPIO0 may support post-boot input, but reset must never be treated as a software user button; physical board/revision wiring, pullup and boot safety need separate confirmation. One RGB pixel can simulate red/green policies with priority rules; it is not the same hardware as two independent Hak5 LEDs. TX/RX LEDs are separate schematic circuitry, not proven firmware-controlled status outputs.

User-provided individual-device evidence confirms16MiB flash, native ROM USB Serial/JTAG recovery, disabled encryption/secureboot and reported8MB embedded PSRAM. Repository core3.3.0 profile deliberately keeps PSRAM disabled, uses USB-OTG/TinyUSB, QIO80MHz and the established two0x740000 slots. ROM USB mode is not application USB mode. Schematic module designation alone does not prove the exact individual module variant or all GPIOs. No board was accessed in Stage9.

Plain source streaming is bounded to256KiB,8192 lines,512 UTF-8 bytes per line; reader64-byte cache with256 consumed bytes/8 parsed lines per update. Expression256 bytes/128 tokens/depth16/16 instruction budget, symbols16, constants16/2048 bytes, functions16/calls8 and control8 remain fixed. SD avoids whole-script RAM; READ compatibility command still uses whole-file readString and an empty string conflates failure with an empty file. Real production storage paths validate .txt/.duck and prepend /scripts/ for SD, while mocks replace parsing/adapters; host tests do not prove mount/path/full-disk behavior. Web script editing/settings/uploads can mutate source or device state outside live-command ownership; same-size source modification during a run is not detected by size checks. Boot LED/autorun delays and first MSC-image creation are blocking despite cooperative script execution.

No audit buffers enter firmware; staticRAM/stack/heap are unchanged. Host allocation probes prove their narrowly instrumented paths, not zero allocation for String parsing/file/web operations. Stage8 compiler stack estimates remain applicable because compiled production sources are unchanged; actual task-stack high-water, fragmentation, web/USB concurrency and SD latency await hardware.64KiB coredump capacity is not a promise to capture every task's memory.

High Sierra10.13.6 initial validation should use a fresh TextEdit plain-text document, matching input source, visible harmless fixtures and documented keyboard-layout assistant handling. Verify US/DE punctuation, AltGr/Option/dead keys, key release after cancellation/backpressure, actual timing, host lock replies and USB re-enumeration separately. Held letters may invoke macOS accent menus rather than repeat. F-keys/keypad/media/navigation effects depend on host settings. Simulated accepted report bytes do not prove any of these outcomes.

## Remaining reference ambiguities to resolve before implementation

* Full precedence, eager versus short-circuit logic with function effects, power associativity, literal/truncation/shift bounds and implicit value returns: no independent reference runtime established.
* INJECT_MOD is shown both inline (`INJECT_MOD WINDOWS`) and as a separate line before HOLD/RELEASE. Scope across subsequent commands is not fully specified; preserve provenance and add a reference-informed state-machine contract.
* STRINGLN first-tab prose versus rendered spaces and wrong END_STRING example; language-specific aliases have image-only terminator details; expansion/indent/default-delay edge ordering not independently compared.
* Manufacturer/product lengths: dedicated attack-mode page says16 alphanumerics, quick reference/randomization says32; serial prose12 digits versus SERIAL_1337 examples. Randomization page uses RANDOM_CHAR while quick reference/results also use RANDOM_CHARACTER. Both recognized reference spellings are inventoried; neither implemented.
* F0/SCROLLOCK typographical reference entries conflict with normal USB usage/other pages. Do not invent mappings to accommodate likely documentation errors.
* Extension editor metadata, variable name reservation and raw INJECT_VAR packed-key encoding must be tested against an actual compiler/spec revision before claiming interchangeable compiled behavior.

No full-language compatibility claim or completion percentage follows from this audit. Current genuine gaps have reproducible diagnostics; uncertain reference edges retain explicit unresolved status.
