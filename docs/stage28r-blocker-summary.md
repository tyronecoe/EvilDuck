# What Stage28Q blocks, and what it does not

Stage28L deliberately proposed a stronger transport contract than the production backend implements: Accepted requires current correlated full successful IN completion **and** certified safe retirement, framing/epoch validity and uncancelled eligibility. It is an engineering selection, not a universal Espressif or DuckyScript prerequisite. See `stage28l-transport-contract.md` and `stage28q-premise-ledger.md`.

Stage28Q's 37 conditional model PASS groups / 419 assertions and the separately rerun unchanged P's 33 observation groups / 167 assertions are inherited evidence, NOT rerun here. The public/missing-premise profile refuses before register requests. All-true synthetic premises test an implication, not its silicon antecedents. Safe real descriptor reuse remains **UNRESOLVED**. The TRM v1.8 §32.5 (printed/PDF page1242) restricts comprehensive USB-OTG register specifications; public descriptions do not establish every stop-access/no-late-IRQ/posted-visibility/FIFO-scope premise.

P's actual source-body native tests demonstrated mutable descriptor overwrite and deliberately injected early/stale/inconsistent event paths. They are not reproduced silicon failures, duplicate-IRQ reports or a security-vulnerability finding. O's tagged prototype executes real stack/class code with fake controller/OS certificates. M's synthetic lifetime and K01 barrier evidence remains useful, not a real controller certificate.

This blocks **Option A's strict proof**. It does not prove ordinary HID is impossible, the S3 unusable, or parser/runtime work prohibited. The existing production path submits through public TinyUSB APIs, keeps a fixed class-owned copied buffer and follows its stack busy/claim lifecycle. It already has cooperative command phases, held-state merging and clearing retries. Those are useful existing policies, not correlated completion or guaranteed delivery.

The language objective is textual DuckyScript support, not perfect transport certification. Production already implements more device extensions than preview. Preview offers an independently bounded compiler/runtime and tested continuations; replacing production indiscriminately would lose functionality and alter numeric/capacity behavior. Neither implementation language nor a raw numeric payload format decides textual compatibility.

Decision needed: retain A as the only integration acceptance contract, or separately authorize B's local scheduler/submission contract for an explicit opt-in subset. Nothing in this package changes L's approval cells or reinterprets its strict Accepted. If B is selected, its metrics must be called local command completion/submission, never tagged completion, retirement or host acknowledgement.
